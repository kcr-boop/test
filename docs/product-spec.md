# 琴译：AI 古琴打谱小程序

Oct 10, 2026 · @kdpkwk66

琴译把一份五线谱或简谱，变成能直接在古琴上弹的减字谱，并用古琴声音演奏给你听；再用一句话完成伴奏和录音的音频编辑。

## 一、作品概述

| 项目 | 内容 |
| --- | --- |
| 作品名称 | 琴译 |
| 一句话 | 任何一份曲谱，都能变成你在古琴上弹得出来的减字谱 |
| 作品形态 | 微信小程序（个人主体） |
| 服务类目 | 工具 |
| 备案号 | 苏ICP备2026075665号-1X |
| 目标用户 | 古琴爱好者与初学者、琴馆老师、古琴翻弹创作者 |
| 核心能力 | 识谱输入 → 古琴编配与减字谱 → 古琴演奏；自然语言音频编辑 |

古琴使用减字谱记谱，它记录的是“在哪根弦、哪个徽位、用什么指法弹”，而不是音高本身。把一首现代乐曲变成古琴谱，需要懂律制、徽位和指法的专业编配。琴译用算法完成这一步，让琴友不会打谱也能弹自己想弹的曲子。

## 二、功能简介

琴译只做三件事，并把每一件做到可以直接使用：识谱、打谱与演奏、一句话编辑音频。

### 功能一：识谱输入

- **输入：** 五线谱或简谱的照片、截图、PDF，以及 MusicXML、MIDI 文件。可以从微信聊天记录或相册选择，也可以现场拍照。
- **输出：** 一条可编辑的旋律，包含音高、时值、调号和拍号。
- **校对：** 识别结果以简谱和五线谱两种形式展示，用户点任意一个音即可修改音高和时值，改完自动重新编配。

### 功能二：五线谱转古琴减字谱 + 古琴演奏（核心）

- **输入：** 旋律，加上定弦（默认正调）、水平（入门 / 进阶）和风格（流行 / 古韵）。
- **编配：** 自动选调移调；为每个音选定弦位、徽位、散音/按音/泛音；同弦相邻音使用上、下等走手音；配置左右手指法。
- **输出——谱：** 五线谱、简谱、减字谱三谱逐音对照。减字谱为标准合体字形；点任一减字，可看白话说明，如“名指按七徽，勾三弦”。
- **输出——声：** 按谱生成的古琴演奏音频，音色来自真实古琴采样，包含走手音的滑音和琴体共鸣。支持 0.5 / 0.75 / 1 倍速播放，播放时谱面逐音高亮跟弹，可单句循环。

### 功能三：一句话编辑音频（GC-4 自然语言音频编辑）

用户用一句中文说出要求，系统自动拆解并执行。

| 对谁编辑 | 一句话示例 | 系统执行 |
| --- | --- | --- |
| 原曲音频 | “只要副歌，去掉人声” | 截取片段 → 人声伴奏分离，只留伴奏 |
| 原曲音频 | “伴奏移到琴谱的调，慢一点” | 按琴谱调号自动变调 → 变速不变调 |
| 自己的弹奏录音 | “去掉底噪，加点混响” | 降噪 → 混响 |
| 录音 + 伴奏 | “和伴奏混在一起，古琴大一点” | 对齐 → 音量平衡 → 合成一首翻弹成品 |

古琴演奏音频与同调伴奏可以直接合奏，用户跟着伴奏弹、录，再用一句话完成混音。

### 基础功能

- **免费预览与单曲解锁：** 每首曲免费查看前若干小节的三谱和试听，确认能弹、好听后再付费。
- **我的琴谱：** 已解锁的曲谱永久可看，可继续修改后重新编配。
- **导出：** 长图、PDF、MusicXML，音频为 MP3。

## 四、解决的实际问题

近年学古琴的人越来越多：2015 年学琴者已超过 20 万人，业内现在估计以百万计。但他们想弹的曲子和能拿到的琴谱之间，有一道门槛。

1. **想弹的曲子没有古琴谱。** 传统琴曲有谱本，而流行歌、影视与游戏音乐大多只有五线谱或简谱，没有减字谱。
2. **自己打谱门槛高、耗时长。** 把一个音变成古琴上的一个弹法，要在散、按、泛和多个弦徽位置中取舍，还要兼顾左手移动和右手指法。初学者做不到，老师编一首也要数小时。
3. **看得懂谱也不知道该怎么弹。** 减字谱不标节奏和音高，缺少可对照的古琴示范音频。
4. **练与录缺工具。** 原曲和琴谱往往不在一个调上，琴友很难跟伴奏合奏；录翻弹还要学专业音频软件。
5. **现有工具只管“打谱”。** 市面上的减字谱软件帮用户输入和排版已有的谱，并不替用户做编配。

琴译把“识谱 → 编配 → 听 → 练 → 录”整条链路放进一个小程序，并把最难的编配交给算法。

## 五、技术开发方案

系统分为三层：小程序前端负责输入与展示；微信云托管上的 API 服务负责用户、任务、支付与存储；计算服务负责识谱、编配、渲染、合成和音频编辑。耗时任务异步执行，前端轮询进度。

（处理流程图见 docs/architecture.md）

编配引擎是整条链路的核心；它定下的琴谱调号也交给音频编辑，用来把原曲伴奏移到同一个调。

### 5.1 模块方案

| 模块 | 方案 | 关键点 |
| --- | --- | --- |
| 识谱：文件 | 用 music21 解析 MusicXML / MIDI，多声部时自动提取旋律声部 | 保留调号、拍号、连音线 |
| 识谱：五线谱图片 | 用光学乐谱识别模型 oemer 将图片转为 MusicXML，支持手机拍摄的倾斜谱面 | 识别后做小节时值校验，异常小节标红提示用户校对 |
| 识谱：简谱图片 | 由多模态视觉大模型将简谱转写为结构化文本，再由规则解析为旋律 | 同样做时值校验；用户可逐音修改 |
| 古琴编配引擎（自研） | 建模七弦定弦与十三徽位置；为每个音生成散、按、泛的全部候选位置；用动态规划（Viterbi）在整首曲上求最优弹法 | 代价函数综合跨弦、左手移动距离、弹法切换和音区舒适度；支持走手音与水平约束 |
| 纯律与徽位 | 按音位置按弦长比计算，距徽位 20 音分以内吸附到该徽，否则记为徽分 | 符合琴人实际取音习惯 |
| 记谱渲染 | 五线谱：生成 MusicXML，由 Verovio 排版为 SVG；减字谱：基于开源减字谱字体组合出标准合体字；简谱：自研 SVG | 三谱逐音对齐，共用同一时间轴 |
| 古琴演奏合成 | 基于古琴采样（七弦的散音、按音、泛音）的采样合成，叠加走手音音高包络与琴体卷积混响 | 音频与谱面共用时间轴，实现跟弹高亮 |
| 一句话音频编辑 | 指令解析 → 操作序列 → 链式调用音频工具。中文规则解析优先，大模型输出 JSON 作为兜底 | 工具：截取、人声伴奏分离（Demucs）、变调、变速（librosa）、降噪、混响、音量与混音 |
| 支付 | 微信小程序虚拟支付（道具直购），服务端签名与发货推送校验 | 按订单号幂等发货，主动查单兜底 |
| 部署 | 微信云托管容器运行 API；重计算放在独立计算节点 | 异步任务队列，前端轮询进度 |

### 5.2 为什么把编配做成求最优路径

同一个音在古琴上往往有三到五个位置可弹。单独看每个音选“最好的位置”，连起来往往左手来回跳、不顺手。琴译把整首曲当作一条路径：相邻两个音之间的“转移代价”反映左手移动、换弦和弹法切换的难度，再用 Viterbi 算法找到总代价最小的一条。这也是初学者模式、流行与古韵两种风格的实现方式：只需调整代价权重。

### 5.3 质量保证

- 编配规则由创始人按实际演奏经验校对，并以创始人翻弹过的曲谱作为标准答案，逐音计算一致率。
- 自动化测试覆盖律制计算、徽位吸附、编配、支付签名与发货幂等。
- 上线后用户的改音与改指法记录（脱敏）用于持续改进编配规则。

## 六、创新点

1. **从“打谱工具”到“自动编配”。** 现有减字谱软件帮用户输入已有的谱；琴译把任意五线谱或简谱自动编配为可弹的减字谱，把琴师的经验变成算法。
2. **把古琴编配建模为最优路径问题。** 结合纯律徽位、散按泛三类音色和左右手工效，用动态规划在整首曲上求最顺手的弹法，并支持按水平和风格调整。
3. **三谱对照 + 白话指法 + 古琴演奏。** 五线谱、简谱、减字谱逐音对齐，配合按谱生成的古琴音频和跟弹高亮，让看不懂减字谱的人也能开始弹。
4. **学术竞赛成果产品化。** 创始人参加 ICASSP 2027 音频编辑挑战赛（GC-4），把“一句话编辑音频”的 Agent 思路落地到乐器练习与翻弹场景。
5. **全链路放进一个小程序。** 识谱、编配、试听、同调伴奏、录音混音都在微信内完成，无需安装专业软件。
